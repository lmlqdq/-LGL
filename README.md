# 流光启动器 (Liuguang Launcher)

一个原生 Windows 的 Minecraft Java 版启动器，C# / .NET Framework 4.8 手写实现，**零第三方依赖**（JSON 解析、HTTP 下载器、UI 全部自研），编译后只有一个 exe。

> 说明：本项目**没有使用 PCL2 的任何代码**。PCL2 的许可证不允许改包再发布，所以这里是按 Minecraft 官方启动协议从零实现，产品结构参考了 PCL 与美西螈（Axolotl）启动器的思路：实例化版本、国内镜像、Modrinth 资源广场、自动装前置。

---

## 一、编译（10 秒，不需要装任何 SDK）

双击 **`build.bat`**。

- 脚本会自动定位 Windows 自带的 C# 编译器（`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）
- 编译成功后在当前目录生成 **`流光启动器.exe`**（约 300~400 KB）
- 依赖：系统自带的 .NET Framework 4.8（Win10 1903+ / Win11 默认已有）

编译失败时把黑窗口里的报错贴给我，我按行修。

想手动编译也行：

```
"%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /target:winexe /out:流光启动器.exe ^
  /win32icon:icon.ico /win32manifest:app.manifest ^
  /r:System.dll /r:System.Core.dll /r:System.Drawing.dll /r:System.Windows.Forms.dll ^
  /r:System.IO.Compression.dll /r:System.IO.Compression.FileSystem.dll src\*.cs
```

## 二、首次使用流程

1. 双击 `流光启动器.exe`（绿色版，配置和游戏都放在 exe 同目录）
2. 进 **设置**：确认玩家名（离线用）、内存、是否开国内镜像（默认开）
3. 进 **下载**：
   - 选一个原版版本 → **安装原版**
   - 想装模组就再点 **安装 Fabric**（先选中对应的原版版本当底座）
4. 回 **主页** → 选实例 → **启动游戏**
5. 进 **资源** → 搜索模组 → **安装选中资源**（会自动下载 Forge/Fabric 前置依赖）

## 三.五、1.1.0 改了什么

**1. 主题换成白色**
整体从深紫黑改为浅色：页面底 `#F3F5FA`、卡片白、文字近黑 `#1C1F2C`。原来写死在控件里的深色（禁用按钮、开关关闭态、进度条轨道、日志框、输入框）全部收进 `Theme`，换主题只要改一个文件。

**2. 液态玻璃质感**
整窗共用一张「柔光壁纸」位图（浅色渐变 + 4 个主题色光斑），每个卡片按自己在窗口里的位置把壁纸对应区域画一遍，再叠 `白色 140/255` + 顶部高光 + 底部积光 + 内外双层玻璃边。

- 侧栏、标题栏、状态栏是「很淡的白」叠在同一张壁纸上，所以光斑会从栏里透出来
- 卡片之间、卡片与页面之间不会出现接缝，因为壁纸坐标是统一的
- 想更透 / 更实：调 `Theme.GlassAlpha`（140 是默认值，越小越透，190 以上接近实心）

> 说明：WinForms 的子控件是独立 HWND，拿不到桌面的像素，所以做不了 CSS 那种 `backdrop-filter` 对桌面实时模糊。这里是等效实现——模糊的是启动器自绘的壁纸，观感一致，但不会把桌面壁纸糊在卡片后面。

**3. 自动下载 Java**
启动时按版本 `javaVersion.majorVersion` 检查：本机有同版本就用，没有就自动下载。装在 `.minecraft\runtime\java-{版本}\`，用 `java.path` 记下真实路径（JDK 压缩包有一层版本目录，不会拍平）。下载源按实测速度排序：华为云 OpenJDK → Azul Zulu → 微软 OpenJDK → Adoptium，详见下面 1.2.1 那节。设置页有「自动下载 Java」和「导入本地」两个按钮。

**4. 启动前环境自检**
每次点启动先核对：客户端 jar、逐项依赖库、natives（.dll）、资源索引、逐项资源文件、log4j 配置。缺什么就自动补什么，补完还缺才报错，并且报出**具体缺哪几项**。以前是直接抛「缺少游戏核心文件，请重新安装」，只能靠猜。

**5. 三个会导致「装了也启动不了」的隐性问题**
- 多个资源名指向同一个 hash 时，多个线程会同时写同一个文件，`File.Move` 冲突导致整批下载被判失败 → 现在按目标路径去重
- 单个文件失败就中断整批，留下半装状态 → 现在其余文件继续下完，最后汇总报失败个数，重试时已完成的文件会被 SHA1 校验跳过
- 1.12 及以前强行用 Java 17 启动必崩 → 需求 Java 8 时不再拿高版本顶替，本机没有就自动下载 Java 8

**6. 启动失败看得见了**
游戏进程 20 秒内退出会把退出码打到状态栏（"游戏启动失败（退出码 1）"），配合主页日志能直接定位是缺组件、内存不够还是模组冲突。

## 三.六、1.2.0 改了什么

**1. 窗口拖不动 —— 修掉了**
无边框窗口的标题栏是自绘 Panel，鼠标落在它上面时窗体根本收不到 `WM_NCHITTEST`，所以坐标全被子控件吃掉；退一步给窗口发 `WM_NCLBUTTONDOWN + HTCAPTION` 让系统进入移动循环，对 `FormBorderStyle.None` 的窗口也不可靠（没有 `WS_CAPTION`），表现就是按住标题栏纹丝不动。现在拖动改成进程内实现：按下时记下光标与窗口原点的偏移，`MouseMove` 里直接设 `Location`，不依赖任何窗口样式。标题栏、侧栏空白处都能拖；四边 7px 内按下仍是缩放（缩放继续交给系统，因为要处理最小尺寸、DPI、吸附）。

**2. 文字底下有白块 —— 修掉了**
WinForms 的「透明」子控件会去回调父控件的 `OnPaintBackground`，而卡片是在 `OnPaint` 里画的玻璃，于是每个 Label 背后都压出一个白方块。现在 `LgLabel` 不再用透明底，改成直接裁父卡片那张已经算好的离屏表面（`LgCard.Surface`）贴在自己身上——逐像素和卡片一致，接缝为零，文字看起来是「印在玻璃上」。

**3. 状态栏进度条按下展开下载详情**
状态栏右侧有「详情」提示和箭头，点状态栏任意位置（或进度条本身）展开一块详情面板，每 400ms 刷新：当前阶段、文件数 `完成 / 总数 / 百分比`、实时速度与已传输量、正在下载的文件（多线程各自在下的）、失败项。再点一次收起，按 `Esc` 也能收。

**4. 玻璃更透、层次更清楚**
玻璃白从 140 降到 130，光斑饱和度提上来；卡片底缘加了一道「接地阴影」（白底界面上卡片像贴纸，缺的就是这一笔）；圆形色块选择器带勾选态；进度条、导航按钮都改成和所在玻璃栏同一套铺底算法，不再出现比周围更亮的方块。

**5. 版本号**
标题栏和日志里的版本号来自 `Paths.Version`，这一版是 `1.2.2`。

## 三.七、1.2.1 改了什么（Java 下不下来）

**1. 换下载源 —— 按实测速度重排，原来的首选其实是最慢的**

在本机对每个源实际拉 512KB 测速，结果和原来的排序完全相反：

| 源 | 实测速度 | 说明 |
|---|---|---|
| 华为云 OpenJDK `repo.huaweicloud.com/openjdk/` | **1.9 ~ 6.9 MB/s** | 国内 CDN，60MB 的包十几秒下完；只有 x64，且不含 Java 8 |
| Azul Zulu `cdn.azul.com` | 0.8 MB/s | 覆盖 Java 8 与 32 位，官方元数据 API 很稳 |
| 微软 `aka.ms/download-jdk` | 0.24 MB/s | 仅 Java 11+ |
| Adoptium `api.adoptium.net` | **0.02 MB/s** | 302 跳到 GitHub Releases，国内基本等于不可用 |
| 清华 TUNA Adoptium | 不可用 | 目录页能打开，但 zip 直链无论带不带 Referer、http 还是 https **一律 403** |

所以顺序改成 华为云 → Azul → 微软 → Adoptium，清华那条线路整条删掉（留着只会白等一次超时）。代码里还留了一组 Azul 的固定直链（8 / 21 / 25），命中就不必多发一次 API 请求；直链都失败时再问 Azul / Adoptium 的 API 要最新地址。

**2. 「三个源两秒内全部失败」其实不是源的问题**
日志里出现过 `NameResolutionFailure` × 3，而同一时刻 5000 多个游戏资源是下成功的。那是本地 DNS 解析器在高频查询后进入负缓存期的典型表现——已解析过的域名还能用，新域名一律失败。这种情况换源没有意义，所以现在：单个源 DNS 失败会等 4 秒重试一次；**连续两个不同域名都解析失败就直接短路**，弹一段能操作的说明（等 1~2 分钟 / 把 DNS 改成 223.5.5.5 / 走离线导入），而不是让用户对着一个源一个源地超时。

**3. 设置页新增「导入本地」**
下载源全都不通时的兜底，完全不联网：选一个自己下好的 JDK 压缩包（`..._windows-x64_bin.zip`）或已装好的 `java.exe`，解压/复制进 `runtime\` 即可。导入后会检测包里**实际**的大版本，按实际版本归位到 `java-{实际版本}`，避免把 Java 21 塞进 `java-25`、等启动时才崩。

## 三.八、1.2.2 改了什么（游戏起不来，退出码 1）

现象是点启动后一闪就退，日志里只有三行：

```
Exception in thread "main" java.lang.NoClassDefFoundError: com/mojang/jtracy/TracyClient
	at net.minecraft.client.Minecraft.<clinit>(Minecraft.java:273)
```

**根因不在 jtracy，在库的去重键。**

`VersionMeta.Key()` 以前只取 `group:artifact`（例如 `com.mojang:jtracy`），而 1.19 之后原版把 native 从库条目里的 `classifiers` 拆成了**独立的库条目**：

```json
{"name": "com.mojang:jtracy:1.14.38"}
{"name": "com.mojang:jtracy:1.14.38:natives-linux",  "rules": [...]}
{"name": "com.mojang:jtracy:1.14.38:natives-windows", "rules": [...]}
```

`MergeLibraries` 按 key 覆盖，于是后面每一条 native 都把前一条**顶掉**，最后这个库只剩 `natives-windows` 一条。主 jar 既不下载、也不进 classpath —— `TracyClient` 这个类自然找不到。

同一个 bug 还有一个连带后果：`natives-windows` 和 `natives-windows-arm64` 在这份清单里 **rules 完全一样**（都只写 `os.name=windows`），arm64 排在后面，所以 x64 机器最后拿到的是 arm64 的原生包。

**改了两处：**

1. `Key()` 改为 `group:artifact[:classifier]` —— 仍然不含版本号（Fabric 这类子版本要能覆盖父版本的同名库），但把 classifier 算进去，主 jar 与各 native 包从此互不覆盖。
2. `IsAllowed()` 增加一条清单里查不到的约束：classifier 里带 `arm64` 而当前不是 ARM64 机器时直接排除（`Util.IsArm64` 读 `PROCESSOR_ARCHITECTURE`）。

修完之后该版本应有的依赖库从 **56** 项变成 **64** 项，多出来的 8 项正是被顶掉的主 jar。

## 三.九、1.2.3 改了什么（液态玻璃「看不见」）

用户报的是「没有液态玻璃效果」—— 界面一片发白，看不出玻璃质感。这次是第二次报，上一次他说的是「液态玻璃真模糊，透明一点」。

**先说结论：之前两版都漏掉了玻璃最关键的一笔 —— 暗面。**

在此之前，`PaintGlass` 里的每一层叠加全是 `(255,255,255,a)`：白色玻璃底、斜向光带、顶部高光、底部积光。全部在**提亮**，没有一层在压暗。结果就是：

- 卡片永远比壁纸「更白」，而不是「透出壁纸」
- 卡片中段（顶部高光衰减完、底部积光还没开始的那 40% 面积）亮度完全恒定
- 一块亮度恒定、边缘描着高光的浅色矩形，人眼读成的是**白塑料板**，不是玻璃

真实玻璃有亮面也有暗面：光在厚度里被折射、吸收，中下部会沉下去一层冷灰。缺了这一笔，其他所有高光都是白搭。

**改了什么（`Theme.cs` 为主）：**

| 项 | 改前 | 改后 |
|---|---|---|
| 壁纸明暗差 | 243,250,252 → 214,233,238（差 29） | 240,252,254 → 183,213,223（差 57），66° 斜向三段 |
| `GlassAlpha` | 130（51% 纯白，把背景冲平） | 66（26%，背后颜色能透出来） |
| 折射暗区 | **没有** | 新增：y 在 [0.22h, 0.74h) 之间叠一层 36 alpha 的冷暗，两端归零 |
| 整体冷调 | 没有 | 新增 14 alpha 青调，把「白」压成「冷白」 |
| 磨砂噪点 | 1400 点，alpha 5~18 | 2600 点，alpha 26~54，双层错位 |
| 光斑 | 4 团，半径按长边 | 5 团，半径按对角线（宽窗口下不再拉成横条）+ 焦点缩放 |

暗区峰值定在 36 是有上限的：再高会让次要文字 `Theme.SubText` 在暗区上的对比度掉到 3.4:1 以下。

**顺带修掉的三个真 bug：**

1. **`Surf.Of` 让每个控件结出白块**：父级是 `LgCard` 时它返回 `card.Fill`（纯白、alpha 255），于是按钮、开关、输入框、进度条都在自己的圆角**外面**刷一块纯白，把底下的玻璃盖掉。现在改为返回 `Color.Transparent`，真正该画什么由新增的 `Surf.PaintCardBacked()` 从父卡片的离屏表面逐像素裁过来 —— 圆角外是真的玻璃，不是一块对不上的平涂色。
   > 这里踩过一次坑：第一版把它改成 `fill.A < 255` 才返回透明，但 `Color.FromArgb(246,252,253)` 是 3 参重载、alpha 恒为 255，条件永远不成立，等于没改。QA 复核时发现并纠正。
2. **`InvalidateWallpaper` 没重置 `wallpaperAt`**：调用方紧接着请求同尺寸壁纸时会命中 150ms 节流分支、返回 `null`，界面在启动初期和换主题后整片纯色。
3. **`CardShade` 被裁在圆角内**：投影画到控件边界就被位图切掉，等于没有外投影。改为贴着圆角外侧画环形投影。

另外，`LgCard` 的玻璃矩形改回铺满整个控件（之前试过四周留 14px 给投影，结果内容整体偏移、首页彩色竖条被压住、`LgList` 右沿被切成缺角），`LgIconButton` 不再用 `PaintGlassBar`（那是给整条栏用的，会把按钮刷成一块死白），`LgProgress` 的栏 alpha 从 132 降到 104。

`Paths.Version` → `1.2.3`。

## 三.十、1.3.0 改了什么（真正的液态玻璃：边缘折射）

前两版做的一直是「半透明白 + 噪点 + 高光 + 描边」。那套东西叠出来是一块亮度平坦、
边缘描亮的浅色矩形，人眼读作**磨砂塑料板**，不是玻璃。所以怎么调白度、调光斑、
调暗面都无效 —— 那些参数只改变**颜色**，不产生**形变**，而人眼判断玻璃靠的是形变。

### 补上的核心：圆角矩形 SDF 边缘折射

新增 `src/Theme.Liquid.cs`，与 iOS 26 / CSS `backdrop-filter + feDisplacementMap` 同源：

1. 对每个像素求圆角矩形的**有符号距离场**（SDF，内部为负）
2. `smoothstep(-band, 0, sdf)` 得到折射权重 `t`：边界处 `t=1`，向内 `band` 处 `t=0`
   → **只有边缘那 13% 在弯，中间一个像素都不动**（这是真实玻璃的光学行为）
3. 位移方向取**径向反向**，幅度 = `t × 强度 × 长边` —— 边缘采样更外面的背景，
   视觉上就是透镜边缘的压缩带
4. 叠加切向的**液化波**（swirl），让边缘不是一条规整圆弧
5. 按位移后的坐标对整窗壁纸做**双线性采样**
6. **色散**：R / G / B 分别用 1.00 / 1.14 / 1.28 倍的位移采样，
   边缘析出极细的青/品红彩边 —— 这是「玻璃」最强的信号，且不依赖背景纹理
7. 轻微高斯模糊 + 提饱和

实现细节：在 1/2 分辨率下计算再放大（结果本来就要糊，画质无损，成本降 4 倍）；
结果按「尺寸 + 圆角 + 窗体坐标」缓存，只有布局变化或换主题才重算，一张 340×210
的卡片约 15ms，正常运行零开销。

### 壁纸必须"有东西可折"

折射是纯几何位移，不改变对比度。如果背后是一片平滑渐变，位移多少都不产生视觉差异 ——
这是之前几版全部失败的深层原因。所以壁纸新增了一层 `MicroTexture`：
19px 周期的极淡斜纹（±6 色阶）。页面上只是"一点亚麻质感"，
但被边缘 30px 的位移错开一个多周期后，会出现明显的**水波状扭曲**。

参数是实测出来的，两个都踩过坑：
- 周期 7px 的细线会被模糊完全抹平，位移白做 → 改成 19px 宽带
- 幅度 11 色阶时整页像条纹墙纸 → 压到 6 色阶

### 其余调整

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| `GlassAlpha` | 40 | **16** | 真折射已在下面一层做完，26% 白会把它重新糊平 |
| 顶部高光 | 78 | 28 | 同上，高光会盖掉边缘折射 |
| 底部积光 | 92 | 50 | 同上 |
| 折射暗区 | 有（36 alpha 压暗） | **删除** | 那是用颜色冒充几何，现在边缘真的在弯 |
| `Liquid.Blur` | — | **2** | 模糊超过 5px 会把 19px 纹理衰减到 1/5，错位就看不见了 |
| 边缘 | 外暗边 + 内白线 | 再加**内侧聚光环**（4px 笔裁掉外侧） | 玻璃边缘把光挤成更亮的一圈，比单线厚得多 |

## 三.十一、1.4.0 改了什么（液态玻璃主题：全局都做成玻璃）

1.3.0 解决的是「一块卡片怎么像玻璃」。这一版解决另一个问题：**整个界面都是玻璃**，
并且把「液态玻璃」做成一套**独立可选的主题**（设置 → 界面主题，点缩略图立即生效并保存）。

### 1. 两套皮肤，同一份绘制代码

`Theme.SetMode(bool liquid)` 只切换三样东西：设计令牌（文字/卡片/描边颜色）、背景图、玻璃参数。
其余所有绘制代码共用 —— 所以液态玻璃不是「另做一个界面」，而是同一套界面换了一层材质。

| | 经典青 | 液态玻璃 |
|---|---|---|
| 背景 | 淡青光斑渐变 | **蓝白 45° 斜条纹**（周期 ≈ 窗宽 1/7） |
| 卡片雾浓度 | 16（6%） | **60（23%）** |
| 折射强度 / 色散 | 1.70 / 0.14 | **2.10 / 0.20** |
| 按钮 | 10px 圆角实心渐变 | **半高胶囊（pill）玻璃** |
| 选中态 | 实色 `CardHover` | 半透明主色 + 内侧白环 |

### 2. 为什么背景要换成蓝白斜条纹

折射是纯几何位移，**它不改变对比度**。1.3.0 用 19px 微纹理是为了让边缘有东西可弯；
但对「整屏都是玻璃」来说，微纹理太细，撑不住大块卡片。参考图给的答案很直接：
**背景本身就是高对比的斜条纹**，玻璃压上去，边缘推出 20-26px 就把条纹错开一个多周期，
中间几乎不动 —— 这才是人眼读作「液态玻璃」的画面。

条纹还有两个必须遵守的数值：
- 周期按**窗口宽度的 1/7** 取（120~240px 之间钳制），窗口越大条纹越宽，比例才稳定；
- 蓝色条纹的 alpha 压到 **88**（再高会在上面放不住深色字），白色间隙留白。

### 3. 全局玻璃：每个控件都过一遍

| 控件 | 做法 |
|---|---|
| 标题栏 / 侧栏 / 状态栏 | 壁纸 + 白色 64~72 + 上打光（液态玻璃下栏更透，条纹能透上来） |
| 卡片 | 全窗壁纸 → SDF 折射 → 雾 60 → 内白环聚光 |
| 按钮 | **胶囊玻璃**：折射底 + 主色玻璃层（半透明）+ 顶部反光 + 内白外蓝描边 |
| 导航胶囊 | 选中态是一颗凸起的玻璃胶囊，两端把条纹挤弯 |
| 输入框 / 下拉框 / 开关 / 进度条 | 全部走 `Theme.PaintPill`（同一套玻璃胶囊画法） |
| 列表行 | 逐行裁父卡片的玻璃表面，整列看起来是一整片玻璃 |
| 图标按钮 | 悬停浮出一颗小玻璃胶囊 |

新增 `Theme.PaintPill`：小控件的玻璃底。**卡片里的小控件不做折射**，直接裁父卡片表面 ——
卡片内部本来就是平滑的玻璃面，对平滑面做位移看不出任何变化（折射只移动结构，不改变对比度），
白算一遍还掉帧。只有直接压在页面条纹上的控件（导航、页面级按钮）才真的跑折射。

### 4. 折射的两个上限（踩过的坑）

位移量原本与「长边」成正比：700px 宽的卡片边缘会被推出 **80px**，
整块玻璃变成一面哈哈镜 —— 背景被放大、条纹糊成一片，像塑料膜不像玻璃。
现在按参考图里 380px 胶囊的观感反推：
- 折射环带 `band ≤ 56px`
- 位移 `≤ 26px`

边缘能看出弯，中间几乎不动 —— 这才是"厚玻璃"的读法。

### 5. 顺手换掉的原生控件

原生 `ComboBox` 会画出系统灰边框和方块箭头，在玻璃界面上是一块补丁。
`LgCombo` 重写为自绘胶囊 + 无边框圆角弹出层（`LgDropDown`，独立 HWND，
天然支持"点别处就关"）。`TextBox` 也换成 `LgTextBox`，换主题时由 `Theme.ApplySkin`
统一刷新底色 —— 否则切换后原生控件会留一块旧主题的白。

### 6. 怎么切

**设置 → 界面主题 → 点缩略图**。立即生效、立即写盘（`config.json` 的 `Theme` 字段）。
切到液态玻璃会自动把主色换成蓝 `#2F6BFF`，切回经典青换回青 `#0FA3A3` ——
两套皮肤的主色是配套的，不换会撞色。老配置文件没有 `Theme` 字段，按液态玻璃处理。

### 7. 小控件没有背景可弯，只能靠自身材质

`PaintPill` 裁的是卡片表面 —— 那张表面是**平滑**的（雾 60 + 光斑），
没有条纹可弯，所以在卡片里的按钮、开关、输入框上，折射等于没画。
能拉开对比的只剩自身材质浓度。

第一版主按钮用 152/198 的半透明主色，预览图里「启动游戏」几乎和卡片融成一片。
**半透明是手段，不是目的**：按钮先要像个按钮，再谈它有多透。
现在定在 184/222（悬停 198/234，按下更沉），既保留透光感，又有明确的边界。

### 8. 缩略图的两个坑（设置页的主题预览）

`ThemePreview` 不是截图，是按缩略比例重画 —— 重画就一定会踩到「按比例」的坑：

- **描边不能画在同一条路径上。** 内白环 248 画完立刻在上面画外暗线 52，
  两条线坐标完全相同，暗线把白环整圈盖掉，边缘只剩一条灰线，
  胶囊在缩略图里就「看不见」了。必须把暗线画在外扩 1px 的矩形上。
- **说明文字必须有自己的一层底。** 缩略图的对比度是随机的（左半边白条纹、
  右半边蓝条纹），深色字压在蓝条纹上、白字压在白条纹上都读不出来。
  底部 28px 先压一层 60→232 的白渐变，再用深色字。

勾也换成了**主色实心圆 + 白色对勾**：原先「白圆 + 主色勾」在满屏白胶囊里没有边界。

### 9. 栏里的子控件必须用同一个白浓度

标题栏是「壁纸 + 92 白」，侧栏/状态栏是「壁纸 + 104 白」。
里面的图标按钮、导航项、进度条如果只调 `PaintBackdrop`（纯壁纸）铺底，
就会比栏本身**暗整整一档** —— 经典青主题下只有 6 个色阶，看不出来；
液态玻璃主题下压着高对比条纹，直接就是几块偏暗的方块。

所以把浓度提成常量（`Theme.TitleBarAlpha` / `Theme.ChromeBarAlpha`），
并拆出 `Theme.PaintBarFlat`（栏底，不画顶光）：
- 栏本身用 `PaintGlassBar` = 栏底 + 一道顶部高光；
- 栏内子控件用 `PaintBarFlat`。

顶光是按**控件自身高度**算的（顶部 40%），子控件自己画顶光会多出一道
横条上根本不存在的高光 —— 五个导航项就是五道假高光，比暗方块更显眼。

## 三.十二、1.5.0：三套皮肤 + 自定义背景

1.4.0 那套「只有液态玻璃」的做法改掉了：`LiquidMode` 这个布尔值扩成了三值枚举
`Theme.Skin { Solid, Liquid, Millennium }`，并保留 `LiquidMode` 作为**只读计算属性**，
于是二十多处 `if (Theme.LiquidMode)` 一行都不用改就能继续工作。

### 1. 三套皮肤的分工

| | 纯色 | 液态玻璃 | 千禧年 |
|---|---|---|---|
| 背景 | 平涂底色 | 蓝白 45° 斜条纹 | 湖蓝天光 + 斜光带 + 玻璃泡泡 |
| 卡片 | 白卡 + 1px 细边，**不跑折射** | SDF 折射 + 雾 60 | 折射 + 雾 118 + Aqua 顶光 |
| 按钮 | 主色渐变 + 10px 圆角 | 半高胶囊玻璃 | 蓝色本体 + 上半个清漆 + 硬分界 |
| 输入/开关/下拉 | 白底细边 | 玻璃胶囊 | 奶白玻璃 + 顶光 + 灰蓝边 |
| 折射强度 | 0（关） | 2.10 | 0.95（只要一点点弯） |

三者的差别是**结构差别**，不是配色差别：纯色连 `CardShade` / 磨砂 / 边缘聚光都不画，
千禧年则不追求「透明」而追求「亮」—— 清漆比玻璃厚得多。

### 2. 千禧年为什么必须画「泡泡」和「硬分界」

2000 年代那批界面（XP 的 Luna、Vista 的 Aero、初代 iOS、当年的官网按钮）共用一套骨架：
高饱和天光渐变、成群的半透明泡泡、一道横贯画面的镜面反光，
以及按钮上「上半个亮、下半个本色、中间一条明确硬边」的清漆。

最后那条最容易画错：用高斯渐变去过渡会得到**玻璃**，而不是**塑料清漆**。
`Theme.PaintGloss()` 因此分两段画 —— 先一整块柔光，再在 46% 处压一条 1px 的更亮窄带。
缩略图里也一样：先铺白再叠蓝，会得到「白按钮戴蓝帽子」；必须蓝底在上、清漆压顶。

### 3. 自定义背景

`Theme.SetCustomBackground(path)` + `Config.Background`。
用户选的图片**顶替**生成出来的壁纸，三套皮肤共用同一张 ——
它是「一层可替换的底」，不是第四种皮肤。

三个必须处理的点：

1. **按 cover 缩放**（铺满 + 居中裁切），不拉伸：拉伸过的照片一眼能看出来，比裁切难看。
2. **上面压白纱**（整体 46 + 顶部 120 渐隐）：三套皮肤的文字都是深色，
   用户可能选一张深色照片，不压白纱就是「换了张好看的壁纸，字全看不见了」。
3. **用 FileStream 读、读完立刻释放**：`Image.FromFile` 会锁住文件，
   用户之后就删不掉自己刚选的那张图了。

设置页的「界面主题」卡现在是三张缩略图 + 一行背景选择（选择图片 / 跟随皮肤）。
缩略图不是截图，是按缩略比例重画 —— 条纹、胶囊、泡泡、白卡都在，区别一眼可见。

### 4. 配置迁移

`config.json` 的 `Theme`：`liquid` / `millennium` / `solid`。
老配置的 `""` 和 1.4.0 的 `"classic"` 一律解析成液态玻璃 ——
那时界面上唯一的皮肤就是玻璃，迁到「看不出区别」比迁到「看起来坏了」安全。

## 三.十三、1.6.0：把界面从「控件拼装」改成一套设计

1.5.0 之后仍然被说「老套」。这次没有继续调参数，而是把窗口截图下来逐块拆，
发现三个真问题，都不是配色问题。

### 1. 侧栏白得像贴了张纸

侧栏 216px、实心 `(238,245,255)`，把左半边背景整片盖死。
背景的条纹、光斑在那里完全消失，玻璃无从谈起 —— 玻璃的全部意义就是「透出背后的东西」。

改成 **92px 图标轨**：76×64 的圆角块，图标在上、两字标签在下，选中态是一块凸起的玻璃。
`216 → 92` 这一条比任何材质参数都更直接地改变了观感：
用 1/5 的窗口宽度去放五个两字菜单，那是后台管理系统的排法，不是启动器的。

同时删掉侧栏里的第二份品牌区（标题栏已经有一个 logo，重复出现是「不专业」的典型信号），
以及侧栏右沿那条 1px 竖线 —— 现代界面靠留白分栏，不靠描边。

### 2. 玻璃「不像玻璃」，根因是没有模糊

`Liquid.Blur` 原来是 **2**，换算下来只有 1 遍 box blur，等于没模糊。
于是卡片的折射层透出的是**清晰的**条纹图：正文压上去会花，只能靠加厚白雾去压，
白雾一厚，玻璃就变成一块磨砂白板 —— 怎么调参数都在「糊」和「白」之间反复。

真玻璃透出来的是**被模糊过的背景色晕**，不是一张清晰的图。
把 `Blur` 提到 12（6 遍 box blur），白雾才敢从 60 减到 34，
「既透又能读字」这个看起来矛盾的要求，靠模糊这一层同时满足。

连带两处：
- 背景条纹浓度 88/40 → 190/96，周期 1/7 → 1/8。
  折射位移的是背景像素，背景本身没有高频结构，位移前后就是同一片浅蓝。
- **去掉 `MicroTexture`**。那层 19px、32° 的细纹和 45° 条纹不同向，
  叠在一起互相干涉，是「条纹糊成云雾」的另一半原因。条纹本身就是折射需要的结构。

### 3. 日志区是一块纯白矩形，还挂着系统滚动条

`TextBox` 自绘不了，浅色时它就是一张贴上去的白纸；右边那条灰白滚动条更是改不了颜色。
整屏最廉价的地方就是它，比任何配色问题都刺眼。

改成**深色玻璃板**（`LgCard.Dark`）：
- 板子和 `TextBox` 用**同一个纯色** —— 只要有一点渐变，矩形边界就会切出一道颜色台阶；
- `ScrollBars = None`，回看用滚轮（原生滚动条是 Windows 画的，颜色写死）；
- 内侧 1px 白光，深色板的边缘必须有这道线，否则读起来是「黑塑料」；
- 空日志时居中显示一句占位，否则那块黑板就是一个洞。

### 4. 边缘那圈白线

内白线原来是整圈同一个 215 —— 在浅蓝背景上读起来就是「描了一圈白边」，
像贴纸的裁切线，把折射挤出来的弯折全盖住了。
改成**垂直渐变笔**：顶部 240、底部 66。光从上方来，下沿只该反射一点环境光。

### 5. 排版

- `H1`：22pt **Bold** → 19pt **Regular**。22 粗在 96DPI 下是 29px 的黑体块，
  那是对话框标题的形态；页面标题靠「大 + 细」拉层级，加粗反而吵。
- 主卡 196 → 172 高，各段间距重排到接近均匀。
- 删掉卡片左侧那条彩色竖条 —— 老式 dashboard 的标志性装饰，纯装饰，不承载信息。

### 6. 一条工程经验：截图不能信 PrintWindow

验证界面时先用了 `PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)`，
结果抓到的是**另一个页面**的内容，日志却写着 `切页：0`。
无边框自绘窗口 + 双层缓冲下 `PrintWindow` 会返回不可靠的表面。
最终用 `SetWindowPos(HWND_TOPMOST)` + 屏幕截图，并且**启动、置顶、截图、关闭必须在一个进程里做完** ——
工具每条命令结束会清理它启动的进程树，分两次调用，第二次窗口已经没了。

## 三.十四、1.7.0：视频过场动画 + 默认壁纸换照片 + 按键动画

三件事：点「启动游戏」放一段视频过场，默认背景换成 Minecraft 日落草原照片，
交互控件补上 hover / 按下的平滑过渡动画。

### 1. 视频过场动画（启动游戏时播，任意键跳过）

用 Windows 自带的 Media Player 播放 `splash.mp4`。**播放时机是点「启动游戏」之后**，
不是启动启动器时 —— 启动器要秒开，片头不能拖慢它；真正值得「过一下」的是
按下启动按钮、等游戏起来的那几秒，视频正好把这段卡顿盖住。为什么这样接：

- **零依赖**。项目用系统自带 `csc.exe` 编译，没有 `tlbimp` 工具，生成不了 `Interop.WMPLib.dll`。
  所以不用 ActiveX 的强类型封装，而是用 `AxHost` 子类 —— 它是 `System.Windows.Forms` 内置类型，
  传一个 CLSID，.NET 通过 OLE 接口在运行时动态实例化 WMPlayer.OCX 控件。
- **视频控制走晚绑定**。OCX 暴露的 `URL` / `controls.play()` / `playState` 用
  `Type.InvokeMember` 反射调用，不依赖任何 Interop 程序集。
- **`uiMode = "none"`** 关掉底部控制条。默认的 `"full"` 会露出「正在播放 splash … 千比特/秒」，
  那会瞬间戳穿「这是过场动画」的错觉。
- **视频是外部文件**（`splash.mp4` 放在启动器目录）。它 64MB，打进 exe 会让程序体量翻十几倍；
  而且这是用户随时想换的素材，做成外置文件才换得动。文件不存在就静默跳过，不挡启动。

跳过：任意键 / 任意点击立即结束过场。按键走 `ProcessCmdKey` 而不是 `KeyDown`，
因为 Tab / 方向键 / Enter 在 WinForms 里被当成对话框导航键，`KeyDown` 收不到。

### 2. 默认壁纸换成日落草原照片

液态玻璃的默认背景从「程序画的蓝白斜条纹」换成一张内嵌的 Minecraft 日落草原照片。
关键点：

- **照片作为内嵌资源打进 exe**（`wallpaper.jpg` → `/resource:...,Liuguang.default_wallpaper.jpg`），
  单 exe 就能跑，不额外带文件。`build.bat` 优先读根目录 `wallpaper.jpg`，换图就是替换这个文件再编译。
- **和自定义背景走同一套处理**：cover 缩放 + 白纱 + 顶部渐隐，保证深色文字在任何亮度上读得出来。
  照片是暖色调，比原来的蓝白条纹更需要这层白纱压住。
- **读不到资源就退回程序画的条纹**。资源被剥离 / 打包异常时，界面不会裂开。

### 3. 按键动画：过渡要连续，不能瞬跳

之前所有控件的 hover / 按下 / 开关切换都是「布尔值瞬切」——鼠标一进按钮颜色「啪」地跳，
一点开关滑块「咔」地瞬移。那叫「有状态」，不叫「有动画」。这次补上一个全局补间引擎
（`Anime.cs`），一个共享 Timer 驱动所有缓动：

- **按钮**：hover 淡入（主色浓度连续过渡）、按下时整体缩到 0.96 再弹回，文字下移 1px。
  这是「按键动画」里最直观的一条 —— 给鼠标一个物理回弹反馈，接近 iOS 液态玻璃「按进水面」的手感。
- **开关**：滑块从一头**平滑滑**到另一头，轨道点亮程度跟着插值，不再是瞬移。
- **图标按钮**：悬停时玻璃胶囊的雾浓度、文字颜色都做连续渐变。

缓动是「指数逼近」`current += (target - current) * rate`，视觉是「起手快、落定缓」的
ease-out，和 CSS 一个味。收敛到误差 < 0.002 自动移除，全部收敛后停表，不空转。

### 4. 一个坑：AttachInterfaces 的签名

`AxHost` 的可重写方法是**无参数的** `AttachInterfaces()`，底层 COM 对象用 `GetOcx()` 拿，
不是 `AttachInterfaces(object)`。写错签名 csc 直接报 CS0115「没有找到适合的方法来重写」。

## 三.十五、1.8.0：去噪点 + Forge 安装器 + mod 下载放开

用户反馈三件事：液态玻璃「全是噪点，我要透明」、mod 下不了、forge 没有，并点名「看 PCL2」。

### 1. 噪点的真正来源：磨砂颗粒，不是折射

之前为了让玻璃「有质地」，在每块玻璃上铺了两层 64×64 的随机噪点图（`Frost()`，
白点 alpha 12~29、暗点 9~21）。这层东西叠在折射引擎 + 照片壁纸上，就是用户说的满屏彩噪。

修复：**删掉 Frost**。真玻璃的「糊」应该由折射引擎里的 box blur 提供，噪点是磨砂塑料
的手法，不是液态玻璃。同时把切向液化波 `Liquid.Noise` 归零、`Blur` 12→16、`GlassAlpha`
34→24，玻璃才读作「通透」而不是「磨砂白板」。

日志卡片也从纯色实底改成「折射 + 半透明深色玻璃膜」，不再是一块黑塑料。

### 2. Forge 安装器（完整 processor 流水线）

对标 PCL2 的完整安装，不是「下个 universal jar 糊弄」。关键认知：**Forge 1.13+ 的最终
client.jar 不在 maven 上（404）**，它是 binarypatcher 用 installer 里的 `data/client.lzma`
与原版 jar 实时打补丁生成的。只下 libraries 不跑 processor，启动会缺 `net.minecraftforge:forge`
主 jar，游戏起不来。

流程：`promotions_slim.json` 拿版本号 → 下 installer.jar → 解压 version.json +
install_profile.json → 复用 VersionInstaller 下齐库 → 用系统 Java 跑 client 侧 processor
（installertools 的 MCP_DATA/DOWNLOAD_MOJMAPS/MERGE_MAPPING → jarsplitter 拆原版 jar →
ForgeAutoRenamingTool → binarypatcher 打补丁）。

三个容易写错的点（都踩过）：
- **占位符语义**：`{KEY}` 指向的 `[maven坐标]` 大多是「输出路径/中间产物」，不下载；
  只有 args 里以 `--input [坐标]` 形式出现的才是下载源。
- **installer 内路径**：`/data/client.lzma` 要从 installer jar 解压到缓存，binarypatcher 的
  `--apply` 要的是真实文件路径。
- **`-cp` 不读 MANIFEST**：processor 工具的主类必须显式指定（installertools/jarsplitter/
  binarypatcher 都是 ConsoleTool，FART 是 `net.minecraftforge.fart.Main`）。

### 3. mod 下载放开

ModsPage 原来「原版实例 → 直接 return（提示先用 Fabric）」把用户挡死，误以为 mod 下不了。
删掉这段硬挡，原版也能搜；Forge/NeoForge 实例的 loader 名由 `LoaderName()` 正确返回。

## 五、常见问题

**启动报 "没有找到可用的 Java 17"**
1.1.0 起不会再有这个错：启动时会自动下载对应大版本的 Java，装在 `.minecraft\runtime\java-17\`（只下一次，约 40-60 MB）。1.2.1 起下载源是 华为云 → Azul → 微软 → Adoptium。若全部不通，先看弹窗里是不是写着「域名解析（DNS）无响应」——那是本机 DNS 的问题，等一两分钟重试或把 DNS 改成 223.5.5.5 即可；也可以到 **设置 → Java 运行环境 → 导入本地**，选自己下好的 JDK 压缩包离线安装。

**下载很慢 / 卡住**
设置里打开「使用国内镜像」（BMCLAPI），或把线程数调到 16。

**安装时报 `client-1.21.2.xml 下载失败（HTTP 404）`**
镜像站（BMCLAPI）只收录了 `v1/objects` 下的 jar 大文件，log4j 配置这类几百字节的小文件返回 404。1.1.1 已修：改写地址时按扩展名判断，非 jar 一律走官方源；同时下载器加了「镜像失败自动回落官方」的兜底，任一源缺档都不会再让整批安装失败。日志配置本身缺了也能进游戏，现在不再算作必装项。

**搜索资源一直转圈**
Modrinth 在部分网络下需要代理。搜索走 `api.modrinth.com`，下载走 CDN。

**Forge / NeoForge 装不了**
当前只内置 Fabric 安装。Forge 的安装器逻辑（installer jar 解包 + processors）比较复杂，属于下一阶段要补的模块；现在可以用 Fabric 生态，或手动把 Forge 版本目录丢进 `.minecraft/versions/`，本启动器能识别并启动。

**正版登录**
当前是离线登录（离线 UUID）。微软 OAuth 登录需要注册 Azure 应用并做 device code 流程，属于下一阶段。

**杀软报毒**
因为是无签名的新 exe + 会启动 java 进程，可能触发启发式误报，加白即可。
